# Publication privacy

The exported source tree excludes personal account databases, wallet receipts, test identities/configuration, credentials, private keys/certificates, session exports, process memory, private screenshots, logs, crash dumps, full game files and editor caches. Historical machine-specific launchers and runtime evidence are not exported. The dashboard preview in `docs/images/` uses disposable synthetic data.

Machine-specific names, home/workspace paths, hostnames, Steam account identifiers and actual test-server addresses were removed or replaced with portable paths and placeholders. Loopback, wildcard, synthetic test addresses and documentation-only TEST-NET addresses may remain. The endpoint patcher also requires the original game's public service address constants as exact rewrite targets; those are shipped protocol data, not the preservation operator's addresses.

The destination originally held a single initial commit containing only `.gitattributes`. Its Git metadata was preserved privately outside this directory and the publication repository was initialized fresh with a neutral project identity. It has no remote and no imported author history.

An old provisional release archive was deliberately not copied because technical receipts inside it contain private paths. New release artifacts need a separate content/privacy review after construction. Git ignore rules reduce accidental inclusion; they do not sanitize files you explicitly force-add.

Run `python scripts/audit_public_tree.py` before each publication. It examines tracked and unignored files for sensitive/generated artifacts, account-like Steam identifiers, private workspace paths, common token formats and the current machine's username/hostname. It reports file paths and issue categories without printing matched secrets. Review staged files manually too: automated checks cannot recognize every possible secret or personal detail.

## Operator activity monitoring (running servers)

A running backend records player activity for its own operators. This data lives only in the server's state database (`preservation.sqlite3`, tables `activity_sessions`, `activity_logins`, `activity_geo`, `activity_peaks`, `activity_meta`) and is never part of the published source tree.

**What is stored.** For each game session: account ID, the client IP address, platform, client version when the client reports one, start/last-seen/end times, end reason (replaced, timeout, kicked, banned, revoked, `gateway_close:<code>`), the worlds/instances allocated during the session and, when the TLS game gateway is in use, the gateway peer address and last close code. For each login attempt: time, account ID (client-claimed on failures), IP address, route, success/failure and a fixed reason code. Credentials, session GUIDs in API output, packet contents and chat are not recorded.

**Where the address comes from.** The backend uses the TCP peer address, and accepts nginx's `X-Real-IP` header only when the peer is a trusted proxy (`NEBULA_TRUSTED_PROXIES`, default loopback `127.0.0.0/8,::1/128`). The supplied nginx configurations overwrite any client-supplied `X-Real-IP`; `X-Forwarded-For` is ignored. The gateway appends one connection summary per closed connection (peer address, account ID, close code) to `<state>/logs/gateway-activity-YYYYMMDD.jsonl`; the backend ingests these files and deletes each one after its day has passed and it has been fully read. Set `NEBULA_ACTIVITY_SPOOL_DIR=off` on both services to disable this spool, or to a directory path to relocate it.

**Third-party disclosure.** Unless disabled, the backend sends each public (globally routable) IP address it has recorded to the geolocation provider `https://json.geoiplookup.io/<ip>` — one address per request, at most one request per second, from a background task, never on a game request path. Private, loopback and reserved addresses are never sent. Only coarse fields are kept (country, region, city, ISP, organisation, ASN, time zone, connection type, reverse hostname); latitude/longitude are discarded. Results are cached for 30 days. Configure with `NEBULA_GEOIP_ENABLED=0` to disable lookups entirely, or `NEBULA_GEOIP_URL` (must contain `{ip}`) to use another provider. Tell your players that their IP address is shared with this provider, or disable it.

**Retention.** Rows older than `NEBULA_ACTIVITY_RETENTION_DAYS` (default 90) are deleted at startup and daily thereafter; cached geolocation for addresses no longer referenced by any remaining row is deleted at the same time. Database backups made with `deployment/tools/backup_state.py` contain this data for as long as the backups themselves are kept.

**Exposure.** IP addresses and geolocation are returned only by the authenticated internal management API (`/management/v1/users/<id>/sessions|ips|logins`, `/management/v1/monitor...`) to enabled dashboard operators. Diagnostic logs (stdout, `requests.jsonl`, `backend-failures.jsonl`, `gateway.jsonl`) continue to use hashed `actor_ref`/`session_ref` values and never contain addresses. Handle exports from the monitoring views as personal data.
